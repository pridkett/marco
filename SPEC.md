# Marco implementation specification

Marco is a lightweight Go DNS forwarder, filter, and local name service for an active UniFi home network. One binary per resolver serves DNS and an embedded admin console. It covers the DNS, filtering and discovery jobs currently performed by AdGuard Home, CoreDNS with its PowerDNS SQL plugin, and the separate UniFi scraper.

## Release scope

- **First standalone release:** Plain LAN DNS on UDP and TCP, verified NextDNS-compatible DoT upstream, subscription filtering, manual allow/deny rules, blocked-service groups, UniFi discovery, persistent devices and local records, per-client/group DNS policy, query history, and a web console with PocketID-compatible OIDC plus a local username/password.
- **Next encrypted transports:** DoH, followed by DoQ, using the same upstream contract and policy behavior. These extend the upstream side. Encrypted listeners for LAN clients and AdGuard schedule parity are later features.
- Each instance has its own settings and database and can be administered independently. Deliver the package, multi-architecture Linux build instructions, and example startup configuration. Live rollout, Ansible changes and configuration replication are outside the first release. [Future peer configuration](#future-peer-configuration)

New and unassigned clients receive filtered external and local DNS by default. Assign devices to groups or override them individually. Keep the last publishable address of an offline discovered device until confirmed reassignment or an explicit unpublish. A device can remain visible in inventory indefinitely.

## Service and storage

- Build a CGO-free Go binary for Linux amd64, arm64 and ARMv7, with embedded HTML, CSS and minimal JavaScript. Use `net/http`, `html/template`, `embed`, `log/slog` and `database/sql` with a pure-Go SQLite driver. Use `miekg/dns` for DNS wire messages and listeners. Pin dependencies after checking compatibility with the architecture matrix. Evaluate an upstream client library behind a small interface if it reduces transport code and fits the project's chosen license, Go version and resource limits.
- Put startup bindings, the data directory, URL and trusted reverse-proxy settings, node identity and secret references in a deployment file. Resolve secrets from environment variables or mounted files and never include their values in logs, config exports or management responses. Persist mutable DNS config, inventory, source-list artifacts and sessions. Use SQLite migrations, foreign keys, WAL mode and a bounded, serialized write path. Use a versioned canonical config representation for export and distribution, independent of schema migrations.
- Compile validated config, inventory, local zones and filter indexes into an immutable DNS view. A publisher serializes admin commits, UniFi updates and list refreshes, builds the candidate off the query path, checks its base revision, commits durable state, then atomically swaps the view before reporting success. Readers use one view for a full query. Retain the last usable view and list artifacts on update failure. Rebuild the active view on restart before accepting DNS. DNS works from memory with no SQLite, UniFi, list-host or OIDC requests in the query path. Public DNS looks up only the configured upstream when necessary.
- Start DNS independently of OIDC discovery and background integrations. Use bounded caches, connections, refresh workers, request concurrency and query-log queues. Liveness reports the running process. DNS readiness requires a loaded view and working configured binds. Dependency failures appear in detailed status while local and cached DNS remain available. Support an orderly close of listeners, workers and database writes.
- Suggested package ownership is `cmd/marco` for composition, `internal/config` and `internal/store` for configuration and persistence, `internal/dnsserver` and `internal/upstream` for the wire path, `internal/inventory` and `internal/localdns` for discovery and records, `internal/policy` and `internal/filter` for decisions, and `internal/admin`, `internal/auth` and `internal/querylog` for management. Define interfaces at consumption sites with the integration agent. Use the standard library and small dependencies where practical. A Go build produces the complete runtime.

## DNS request contract

### Resolution order

1. Admit only configured IPv4/IPv6 source CIDRs on DNS listeners. Parse a standard one-question IN request, normalize the name for matching, and preserve the transaction ID and original question in the response. Malformed requests receive FORMERR where a response can be formed. Unsupported operations receive NOTIMP or REFUSED as appropriate. Bound UDP to the requested EDNS size, with a configurable server ceiling of 1232 bytes by default, or 512 without EDNS. Set TC for oversized replies and support TCP retry. Set RA for admitted recursive clients and honor RD=0 by answering local data only. Reject transfers and dynamic updates.
2. Select the source policy using the transport peer IP. Apply any deny-all mode. Apply explicit matching manual rules for the selected policy, with client rules ahead of group rules ahead of global rules. At each level an exact match wins over a suffix match, the longest matching suffix wins, and a deny wins a tie. An explicit deny can cover local names. An allow bypasses downloaded filters and service blocks for that matching name. It grants no external resolution to an internal-only policy.
3. Resolve local records, suppression outcomes and authoritative negatives. Return local results before subscription filtering. For split zones, unknown owners may flow to the external branch. Known local owners with missing types get NODATA. Private-zone misses get NXDOMAIN with a local SOA. Never forward private-zone names, configured LAN reverse zones or unpublished local names that are explicitly hidden. An alias for an internal-only client may use only a locally resolvable chain.
4. For external lookups, reject RD=0 and internal-only clients with REFUSED before inspecting the cache or sending a packet upstream. Apply service blocks and enabled subscription filters to the question for filtered clients. Use NXDOMAIN for domain or service blocks by default, with an EDE Blocked when EDNS is available. Use distinct reason codes for client restrictions, manual rules, service blocks, local suppression, subscription blocks and upstream errors. Forward via the configured encrypted pool on a permitted cache miss.
5. Apply the same external policy to names in the returned CNAME chain, and to eligible alias-mode HTTPS/SVCB targets if supported by the chosen parser. A blocked target blocks the original answer. Keep the upstream-response cache independent of client decisions and recheck policy on every hit. Do not send EDNS Client Subnet or client identity upstream by default. Filter rule changes affect the next query that reaches Marco. Existing client-side TTLs still apply.

### Encrypted forwarding and caching

- Implement upstream DoT for the first release, then add DoH behind the same interface. Use DNS message framing specified for DoT and wire-format DoH POST with `application/dns-message`. Support named endpoint pools, address or hostname, port, TLS verification name, optional bootstrap IPs, and an HTTPS URL including any provider-specific path. For NextDNS the node may supply its own endpoint identity. A bootstrap address overrides dialing only, preserving TLS verification/SNI and the DoH HTTP host. Bootstrap must work with Marco down. Use a system/explicit bootstrap resolver independent of Marco or preconfigured IPs. [RFC 7858](https://www.rfc-editor.org/rfc/rfc7858.html), [RFC 8484](https://www.rfc-editor.org/rfc/rfc8484.html), [NextDNS configuration](https://github.com/nextdns/nextdns/wiki/Configuration-File-Format)
- Fail over on timeouts, invalid responses, TLS failures and retryable service errors within one overall deadline. Verify matching questions and compatible response IDs/transport conventions. Treat valid NXDOMAIN and NODATA as terminal and preserve upstream reply semantics. Use a suggested total deadline of 2 seconds, health/backoff per endpoint, and no implicit plaintext fallback. Exhaustion returns SERVFAIL. A configured alternate resolver is authoritative for its own filtering behavior, so the deployment must keep fallback profiles compatible.
- Cache bounded positive and standards-compliant negative responses with aged TTLs and a configurable 300-second ceiling. Key on canonical question/class/type, upstream pool generation and answer-affecting DNSSEC flags/options. Strip client-identifying EDNS options and bypass the cache for unsupported semantics. Rebuild the response envelope on hits, retaining valid DNSSEC data and clearing AD on synthesized responses. Forward DNSSEC data and signaling to a trusted validating upstream. Local synthesis does not perform DNSSEC validation. Do not serve expired answers in v1. Coalesce compatible misses without sharing downstream policy decisions. [RFC 2308](https://www.rfc-editor.org/rfc/rfc2308.html), [RFC 9499](https://www.rfc-editor.org/rfc/rfc9499.html)
- Add upstream DoQ behind the transport interface after DoH. Verify TLS and use the required ALPN and one DNS query per stream. Keep DNSCrypt outside the baseline unless the listener inventory makes it a cutover requirement. [RFC 9250](https://www.rfc-editor.org/rfc/rfc9250.html)

## UniFi inventory and local DNS

### Discovery and client identity

- Implement a read-only UniFi adapter contract that returns a complete paginated site snapshot of clients and adopted infrastructure. Normalize site, device identifiers, addresses, reported name, network/VLAN if available, observation time and presence evidence. First validate the on-site API-key integration against the deployed firmware. Use the existing scraper's local-account behavior as a compatibility adapter if the official API lacks required fields or device coverage on this controller. Use the system trust store or a configured local CA. [UniFi local API documentation](https://help.ui.com/hc/en-us/articles/30076656117655-Getting-Started-with-the-Official-UniFi-API), [Network API reference](https://developer.ui.com/network/v10.0.162)
- Use an internal stable device ID with an identity key based on configured controller identity, site and normalized MAC where supplied, or a stable source ID confirmed for that adapter. Never merge or inherit assignments by shared hostname or IP. Support manual devices and explicit links between interfaces when an admin confirms they belong together. A device may have several observed addresses. Never assume IPv6 visibility from IPv4 data or a private MAC is a permanent identity.
- Store per-device first-seen, last-seen, latest successful site poll, reported labels, admin overrides, address history, presence and publication state. Prefer a valid source last-seen timestamp. For an endpoint documenting connected-only results with no timestamp, use the successful observation time, marked as observed by Marco. A history row without a timestamp contributes no freshness. A timeout, failed page, 429 or auth failure leaves the site's previous data intact. Poll immediately then every 60 seconds by default, reuse sessions where supported, honor Retry-After, and use jittered exponential backoff up to 15 minutes for transient failures, or longer when requested by the controller. Manual refresh uses the same worker and backoff.
- Distinguish connected, absent on the latest complete connected snapshot, explicitly unpublished or displaced address, and controller data unavailable. Display last-seen age and absolute time separately from controller freshness. Missing devices keep their last publishable forward and reverse mappings, name reservations, policy, aliases and history across polls and restarts. They keep answering until confirmed reassignment or explicit unpublish. When rediscovery confirms that a device moved to a new address, replace that address family's old active set using the adapter's documented completeness guarantees. Keep superseded addresses in history only. Stale or legacy-imported addresses never identify a querying client. A complete site snapshot that omits an address observed in that source's active address set invalidates its dynamic source binding. Bindings also age out when sync stops. Use a proposed five-minute maximum for source identity where presence can be verified and prefer a configured DHCP reservation for individually restricted clients. Unknown or reassigned clients use their own eligible mapping or the subnet/default policy.
- Reconcile each accepted snapshot transactionally. A confirmed new owner invalidates the old owner's publishable address and source binding across its forward records, aliases and PTRs even if the old device is absent. Use confirmed live ownership evidence ahead of historical observations. Simultaneous conflicting live claims suppress the dynamic address mapping for both and report a conflict. A conflicting claimed address must not silently inherit an old device override. Mark a reassigned observation superseded so a historical row from a later poll cannot reactivate it. Admin-pinned device addresses require an explicit conflict warning and stop publishing through the device when reassignment is confirmed. Independently configured manual records remain admin-owned and surface any address conflict. Keep enough evidence to explain the decision.

### Names and records

- Publish validated A and AAAA records from observed or pinned addresses, per-device aliases, manual A/AAAA/CNAME/PTR records, and synthesized reverse PTRs for configured LAN IPv4/IPv6 CIDRs. Support several publication suffixes. Serve fully qualified names. Short names work through DHCP search domains or explicit names. Use an operator-provided name first, then a usable UniFi name, then a hostname. Normalize DNS labels deterministically, reject invalid/MAC-shaped labels by default and reserve assigned names persistently. UniFi label changes update the displayed observation. An existing canonical name changes only by explicit promotion or an enabled rename policy. For automatic collisions, keep the current allocation and use a stable suffix on the newcomer. Admin-owned explicit records take precedence at the same owner and expose the collision in the UI. Validate a deterministic primary PTR and expose alternative PTRs only through an explicit setting. Use configurable local TTLs, proposed 60 seconds for dynamic and 300 for static records.
- Support local CNAME chains and return the requested terminal RRset when available. Reject self-links, cycles or conflicting CNAME owners in candidate edits and cap depth at query time. An unresolved local alias stays visible as unresolved in management. Return the alias with the proper local negative result for an absent local target. An explicit public target may be followed only when the client's policy permits external DNS. Apply that policy to the target as well.
- Distinguish split zones for the existing public suffix from private-authoritative zones such as optional `home.arpa.`. For private zones and LAN reverse space, include an SOA on authoritative negatives and never leak misses upstream. For split zones, forward genuine misses for eligible clients while preserving a local owner for all query types. Use explicit local suppression markers where a suppressed discovered name would otherwise fall through. [RFC 8375](https://www.rfc-editor.org/rfc/rfc8375.html)
- Support disabling publication per device and scraper-compatible exclusions by name, address, or pair. A pair matches both conditions. A rule suppresses the matching learned address/name mapping, including corresponding automatic aliases and PTRs, while preserving independent admin records and non-matching observations. A surviving local record at the same owner still answers. If suppression leaves a learned owner with no records, return local NXDOMAIN for that owner. Store these rules as desired configuration so they persist across discovery, imports and restarts. Deleting a managed alias removes it from the compiled view on the next publication.

## Client policies and blocklists

### Policies

- Provide reusable named client groups representing device types, such as trusted, standard, guest, children and IoT. A client can have one effective group and individual overrides for mode, service blocks, subscriptions, upstream pool and manual rules. Unset override fields inherit from the group. An explicitly empty service or subscription selection replaces the inherited selection. Allow shared manual rules at the global, group and client levels. Modes are filtered external plus local, unfiltered external plus local, local only, and deny all. Unfiltered skips subscriptions and blocked-service selections, while explicit manual denies still apply. Source admission and the policy's local/external decision apply regardless of domain exceptions. The effective client policy selects its configured upstream pool or the global default. Provider-side filtering still applies.
- Match an explicit device assignment through a fresh, unambiguous source binding first, then a configured static address assignment, then an optional configured subnet rule, then the global default. The initial configuration has no subnet policies, so unassigned devices are filtered. If configured, longest prefix wins. A static source assignment represents an admin-verified reservation and yields to contradictory live evidence. Reject ambiguous equal-precedence assignments at validation. A DNS packet does not include a trusted MAC or VLAN identifier. UniFi network metadata may help an admin assign a type, and the packet is authorized using its real IPv4/IPv6 peer address. Require client source IP preservation through container networking, routable VLANs and any optional encrypted listener. Source-collapsing DNS relays cannot enforce per-device rules. Any expected gateway DNS relay gets its own explicit policy and visibility in the UI.
- Show the matched rule, source identity age and effective policy when troubleshooting. Support a dry-run decision by client IP and question using the same evaluator as the query path. Disable recursion to the internet at the bind/CIDR layer. Firewall rules belong to the network deployment if it must prevent clients from using an alternate DNS service or connecting to public addresses directly.
- Implement blocked services as named, versioned domain groups compiled by the same matcher. Support group and device selection with a per-device override. In the first release active service selections apply all day. Keep the evaluator time-aware so weekly schedules can be added with an IANA timezone and migration parity later. An explicit matching allow can exempt a name for a filtered client. A service catalog needs a compatible license and pinned version, with custom domain groups for unsupported services. Map the service IDs in a reviewed migration fixture or surface them as unsupported.

### Blocklist lifecycle

- Admins can add HTTPS subscriptions, enable/disable them, assign them to client groups, update on demand, or add reusable allow and deny rules. Accept plain domain and hosts-file lists, exact/suffix manual entries, and at minimum the DNS AdGuard forms `||name^` and `@@||name^`. Treat a hosts-file owner as an exact blocked name. For AdGuard exception rules, apply the winning specificity within subscription rules and let an exception win a tie. DNS names honor label boundaries and are normalized case-insensitively. Catalog all other constructs encountered in the migration dry run, including modifiers, rewrites, regular expressions and client-specific rules. If a configured list contains required unsupported syntax, report it and require compatible support or explicit remediation before activating that list. Do not silently index a partial list. [AdGuard DNS filtering rule syntax](https://adguard-dns.io/kb/general/dns-filtering-syntax/), [AdGuard Home configuration](https://github.com/AdguardTeam/AdGuardHome/wiki/Configuration)
- Fetch off the query path on a staggered schedule, default every 24 hours. Use TLS verification, conditional HTTP, a deadline and bounded decompression. Set initial limits of 32 MiB expanded and 1 million usable entries per source, plus a total index budget tuned by the Pi benchmark. Validate redirects and every dial address. Remote subscriptions may use public addresses only by default. An explicitly configured local file source is scoped to an operator-provisioned read-only directory. Disallow ambient URL credentials and contain other protocols. Report time, content digest, rule counts, parse failures and refresh status per source.
- Match against a compiled immutable index with bounded allocation and no per-query full list scans. Validate a complete replacement before committing it. Keep the last successful artifact through restarts and failed refreshes. Reject unexpectedly empty replacements unless the admin explicitly requested an empty list. An intentional disable applies immediately. A newly enabled required list without an artifact must be staged and fetched before activation so it cannot appear to protect queries while empty.

## Administration

- Embed a responsive console with Simple LLM Proxy's visual cues. Use an indigo accent, neutral cards with quiet borders, light/dark system themes, a responsive horizontal navigation, accessible status labels, and a centered sign-in card. Use native forms or a small same-origin JSON client. Write keyboard navigable forms and tables with visible focus, usable mobile layouts, and text for errors and statuses. Adopt the visual style with Marco's own name, navigation and DNS vocabulary.
- **Overview** shows query, local/cache hit and block counts with recent time ranges, upstream health, list refreshes, UniFi sync and the active local revision. **Devices** shows canonical name, reported name, addresses, network, assigned and effective policy, last seen, controller freshness and published status. Add search and filters, edit assignments and publication, view conflicts, and trigger a poll. **Local DNS** manages zones, manual entries, aliases and suppressions. **Policies** manages client groups, address assignments, exceptions, service selections and rule tests. **Blocklists** shows source health and permits edit, enable, disable, refresh and test. **Query log** filters by client, question, outcome and time where records are available. **Settings** exposes upstream endpoint tests, UniFi status, operator imports/exports and instance status. Mutations return field validation, conflict details on stale edits and a locally applied revision.
- Offer PocketID or another standards-compliant OIDC issuer using authorization code, PKCE S256, one-time state and nonce. Verify issuer, signature, audience, expiry and nonce using a maintained OIDC client. Use issuer and subject for identity and authorize only the configured admin group. Keep role checking server side. Use a single configurable username and password as a simultaneous recovery sign-in even during OIDC outages. Provision or rotate its Argon2id password hash with a CLI that prompts for the password. Use rate limits for local login, constant-time comparisons where applicable and generic errors. Never ship a default password. Fail closed on OIDC errors and expose the alternate sign-in form when configured.
- Use opaque server-side sessions in SQLite, rotated on either login, with a Secure, HttpOnly, SameSite=Lax cookie. Use same-origin CSRF tokens for browser mutations, including local sign-in and sign-out, and reject unsafe cross-origin requests. Admin runs over HTTPS or on a loopback backend behind a configured trusted HTTPS reverse proxy. Trust forwarded headers only from that proxy for the admin surface. Audit account, time, operation, result and config revision for admin changes and redact secrets and private settings where appropriate. DNS admission has its own CIDR rules, separate from admin sessions.
- Query history is configurable and can be disabled, with aggregate counters still available. Provide a bounded asynchronous ring/queue and batched local persistence. Start with seven days or 128 MiB allocated to query data, whichever expires records sooner, with physical growth and WAL accounted for. Store timestamp, node, source IP or configured anonymized identity, QNAME/type, outcome/RCODE, matching rule reference, cache state and latency, with filters and pagination. Default to no forwarding of individual device labels upstream. Under disk pressure, logging may drop entries and must count drops. Keep at least lightweight counts, upstream and poll timings, cache hit rate, refresh failures, process memory and view revision available without full query logging.

## Import, export and offline migration

Provide an offline `marco migrate` command with a read-only inspection mode and an explicit apply step. It accepts operator-supplied, redacted copies. Prefer versioned Marco configuration for repeatable setup. A migration run may also take rendered scraper TOML, a consistent SQLite backup of `hostnames.db`, and sanitized AdGuard configuration. No network calls are needed for inspection or import. Subscription downloads may be staged afterwards. Also deliver `marco validate` for config, `marco export` for portable desired settings, and an SQLite-aware backup and restore procedure for a full instance. Exports omit credentials, query history and sessions. Support a separate state import if the operator wants inventory history in addition to settings.

| AdGuard Home | Review enabled/disabled subscriptions and allowlists, custom rules, persistent client selectors, assigned filter settings and blocked service IDs. Produce a structured preview with accepted records, exclusions, conflicts, unsupported items and warnings. Applying the same import twice must produce the same desired state, without duplicate entries or silent replacement of existing admin edits. Validate the complete candidate before publishing it. Report any filters that remain staged after import. Support one atomic settings edit or import with a base revision so that an out-of-date operator action cannot replace newer changes.

The checked-in Ansible role does not manage the live `AdGuardHome.yaml`. Build representative fixtures from the tracked role and documented configuration. Complete site-specific parity testing only after the operator supplies a sanitized export or a list of the actually used services and rules. The standalone package can ship with its supported feature set documented independently of that site-specific comparison.

## Future peer configuration

A designated leader can push a versioned desired configuration to selected followers over HTTPS with a dedicated shared API key, provisioned on each peer. Each instance remains directly accessible through its own OIDC or local admin login. Authenticate the machine endpoint separately from browser sessions, transmit revision and content digest, validate and compile before applying, support idempotent retries, and show last applied revision and error per follower.

Define field ownership before adding the endpoint. Followers can inspect received settings and edit node-local settings, such as bind addresses and NextDNS endpoint identity. Shared changes go through the leader and followers reject stale pushes. Each follower continues operating on its last valid desired config and list data if the leader is down. Node-local credentials, sessions, query history and audit data stay local. Decide later whether followers poll UniFi independently or also accept a distinct inventory feed. Versioned local export/import provides compatibility and backups for independent instances today.
